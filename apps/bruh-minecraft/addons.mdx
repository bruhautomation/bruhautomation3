The **Add-ons** tab is one screen for everything added to the active world, and a Modrinth browser
to add more. It is the closest a Java server gets to Realms add-ons — and for a house full of iPads,
arguably better.

A Realms "add-on" is a Bedrock *behavior pack*, which no Java server can run. What a Java server
*can* run is anything that lives on the **server**, and that reaches every player whatever they
play on: Geyser translates the result, and nothing is installed on the device.

## In this world

Every plugin, data pack, server mod and resource pack the world has — added from the browser, by
hand, by link or by the `plugins:` option — grouped by kind. A plugin added outside the browser
shows the name and version its own `plugin.yml` declares. Each row says where it stands:

| Status | Meaning |
| --- | --- |
| **Working** | Loaded now |
| **Starts after a restart** | Added since the server started. Plugins, mods and a resource-pack change need a restart; data packs do not — they reload live |
| **Turns on when the server starts** | The server is stopped |
| **Not used** | A resource pack in the library that this world does not offer; **Use in this world** switches to it |

When anything is waiting, a banner at the top says exactly what (*Added VeinMiner, removed
Chairs*) with **Restart now**, and the list refreshes itself until everything reads *Working*.
Each add-on says **Up to date** or **Update to X available**, with **Update** only when there is one.

- **Removing** something another add-on needs asks first. Add-ons put on the server by hand can be
  removed too, wherever the panel can actually remove them.
- **Conflicts are named.** WorldEdit and FastAsyncWorldEdit installed together are both marked,
  with which one to remove. Nothing is removed for you.

## Server software

The server (Paper, Purpur, …) with its Minecraft version and build, and the cross-play plugins
under it — **Geyser**, **Floodgate**, **ViaVersion**, **ViaBackwards** — with their versions.

- Those download their newest build every time the add-on starts; **Update everything now**
  restarts the add-on to do it on demand (players are disconnected for about a minute).
- When a newer Minecraft version is out, **Upgrade this world** takes a backup and moves the world
  to it. A world is **never** moved to a new Minecraft version on its own: the upgrade rewrites the
  world and cannot be undone, and a plugin built only for the old version may stop loading.

## Add more

![Add more: a Search Modrinth box with Search, chips for Everything, Plugins, Data packs and Resource packs, and result cards for Chunky, WorldEdit, EssentialsX (In this world, Working), Terralith, Incendium and Faithful 32x, each with Add to world and Select, and More results](./images/panel-addons-search.webp)

<Steps>

1. **Search.** One search across plugins, data packs, server mods and resource packs, one result
   from each kind in turn — or narrow it with the chips. Only what **this** server can run is
   offered: the server type and Minecraft version decide.
2. **Add.** **Add to world** installs one. Or press **Select** on several cards, across searches and
   kinds, and **Add all to world** in the tray — up to 25 at once, with one answer and one restart
   note at the end.
3. **Restart** if the banner asks. Data packs are live immediately.

</Steps>

**Add your own file or link** takes a plugin URL or a resource-pack `.zip` (up to 250 MB), served to
players on your network by the add-on.

### What each kind does for an iPad

| Kind | Runs on | What Bedrock players get |
| --- | --- | --- |
| **Plugins** | Paper, Purpur, Folia | Everything — they run on the server |
| **Data packs** | Any server type | Everything — they run in the world |
| **Server mods** | Fabric, Forge | Only mods Modrinth marks as needing nothing on the client, because a mod every client must also have is one an iPad can never join with |
| **Resource packs** | Any | Java players are offered the pack on join; Bedrock players are pushed a converted copy by Geyser. Flat block and item textures convert; custom 3D models and sounds do not |

<Aside title="Safe downloads">
Anything an add-on requires is installed with it and recorded as a dependency. Downloads come only
from Modrinth's CDN and must match the SHA-512 hash Modrinth published, or they are refused.
Add-ons are per world (`.bruh-addons.json` in the world folder), like everything else in `plugins/`.
</Aside>

## The one-click plugin options

Beside the browser, twelve popular plugins can be ticked on the add-on's **Configuration** tab and
are resolved from Modrinth on every boot, for your server's Minecraft version (Paper, Purpur and
Folia). `install_viaversion` and `install_viabackwards` are on by default, so clients a version
ahead or behind can still join. EssentialsX, EssentialsXChat, LuckPerms, WorldEdit, CoreProtect,
GriefPrevention, mcMMO, ChestSort, VeinMiner and Spark are off until you tick them — see the
[Reference](/bruh-minecraft/reference/#plugins). Ticking one off does **not** remove the jar; remove
it on the Add-ons tab.

The [Command Generator](/bruh-minecraft/command-generator/) builds commands for the popular
plugins with a form and a copy button.

## From Home Assistant and brAIn

- Services: `bruh_minecraft.list_addons`, `search_addons` (`query`, `kind`, `offset`),
  `install_addon` (`id`, `kind`) and `remove_addon` (`id`).
- [brAIn](/brain/)'s `minecraft_addons` tool uses them: *"add a sit-anywhere plugin to the family
  world"*. Installing and removing need a **Whole house** or **Full admin** agent, not a voice-level
  one, and the answer says whether a restart is needed.
