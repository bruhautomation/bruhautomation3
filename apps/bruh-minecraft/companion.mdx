With [brAIn](/brain/) installed, a companion joins the family in the world and builds what you
ask for in chat. It appears as a small named **allay** beside whoever it is working for, under
the name you gave brAIn in ⚙ › Personality ("brAIn" if you gave none).

![The Companion card on the Dashboard, named Vesper: a status line saying it is listening; Protected places with two named places and an Add place form that can fill in where a player is standing; Ask a question with who to ask and a green and a red pad, each with an answer and a picture; What it did with an Undo button; Questions & answers; and What it said](./images/panel-companion.webp)

Without brAIn the app runs no companion. The Dashboard shows one line: *"Install brAIn to have a
companion play in the world."*

## Play with it

| You do this | This happens |
| --- | --- |
| Type *"build Sam a little bridge"*, *"make the roof red"* or *"put a couch in this room"* | It does it. Something quick is done at once. A build, a room made over or a tree runs as a **job** while you keep playing |
| Type *"lol"*, or talk to another player | It stays quiet |
| Point your spyglass at something and say nothing | It offers two or three ideas on choice pads |
| Point, then talk | "This" means what you pointed at |
| Stand on a coloured pad for two seconds | That pad's answer is given. Each pad has a picture and a floating item, for children who do not read yet |
| Ask about a running job | The job changes |
| Type *"stop the bridge"* | The job stops **and what it changed is put back** |

Everyone gets a named spyglass on joining. Up to five jobs run at once, and more wait their turn.

To send a request longer than one chat line, send it in parts:

```text
1 build a stone tower
2 with a spiral staircase
3 and a red roof
end
```

`cancel` drops it.

## See what it is doing

| Where | What you see |
| --- | --- |
| **Thought bubble** over the allay | What it is doing right now (*"looking at the blocks around you"*, *"placing 340 blocks"*) and a line per job with how far along it is. Everyone in the game can see it |
| **The allay** | Hovers by what it is building, or circles you while it only thinks |
| **Journal** book, named after the companion | What it is doing now, every job, and its recent steps |
| **Boss bar** | A long job's progress at the top of the screen. Bedrock players see it too |
| **Chat** | One line when a job is done. A quick answer shows no bubble |

The bubble and journal need [BRUH Sight](#bruh-sight), so a Paper or Purpur server. On other
server types, steps of work show on the action bar.

## Protect a place, ask a question, undo an action

The **Companion** card on the panel's Dashboard does three things.

- **Protected places.** Name a place, give its x and z (or press **Use …'s spot** to fill in
  where a player is standing) and a radius, then **Add place**. Nothing is ever built inside it,
  whoever asks.
- **Ask a question.** Pick who to ask, type an answer and choose a picture for the green and red
  pads, then **Ask**. The answer shows under **Questions & answers**.
- **What it did.** Every action, each with **Undo**. Undo puts back the blocks that action
  changed and leaves everything else alone.

## Set it up

Open **brAIn › ⚙ › Minecraft**. The section appears when BRUH Minecraft is installed.

| Setting | What it does |
| --- | --- |
| **On or off**, and **say hello** | Whether it plays, and whether it greets the family on joining |
| **Answer every line from the family** | On by default. When off, only lines that start with its name |
| **Give everyone a spyglass** | On by default |
| **Show what it is thinking** | The bubble and journal. On by default |
| **Jobs at once** | 1–5, 5 by default. More wait their turn, and so does a job in the same place as one already running |
| **The family** | Each person as Child or Grown-up, with their in-game names (Bedrock names with the dot) and any nickname a server script shows. Anybody not on the list is left alone |
| **Bedtime** | A switch (or a door sensor) that means bedtime. Children get a goodnight and nothing new starts for them |
| **Limits** | Turns a day, things it does a day, and things it does for one player in a sitting. 0 means no limit, which is the default |
| **Models** | One for answering in chat, one for building |
| **Can ask for anything** | Per grown-up, off by default. See below |
| **What it did** | Everything it did in the world, with **Undo** |

## What it may do

| Who | May ask for |
| --- | --- |
| **Everyone on the family list**, children too | Anything **in the game**: build, change blocks, look around, a question on the pads, time and weather. Anything outside the game is answered *"I can't do that from the game"* |
| **A grown-up with Can ask for anything** | Everything brAIn's chat can do: game modes, items, teleports, any console command, any block anywhere, and the house |
| **Anybody not on the list** | Nothing. They are left alone |

- A child is never told about another child. Children never get **Can ask for anything**.
- **Can ask for anything** is only used while the server checks accounts: `online-mode` on, or
  Bedrock players signed in through Floodgate. An unchecked name could be anybody.
- A house change follows brAIn's permission setting. With *act without asking* off, it waits for
  a Yes in brAIn and on the phone.

<Aside title="Limits the app enforces itself, whoever asks">
- It summons only its own allay and removes only its own entities.
- It plays only gentle sounds, quietly, to one player.
- On its own it builds only into empty space on natural ground, never in a **protected place**
  or next to a build.
- It backs the world up before anything large.
- It logs every action with an **Undo**. A grown-up's trusted edit may change any block, and
  every block's state is saved first, so Undo still puts it all back.
</Aside>

## More things to ask for

| Ask for | What happens |
| --- | --- |
| *"This is Sam's room"* | The place is named (`label_place`), so *"put a couch in Sam's room"* works without coordinates |
| Maps of your builds | Finished maps are drawn from the saved world and put in a player's inventory, named A1, A2, B1… so they hang edge to edge in item frames (`render_maps`) |
| A skin | A skin is put on a player through SkinsRestorer (`set_skin`) |
| A script | brAIn writes a Skript script or a data-pack function into the running world, loads it without a restart and hears any errors (`write_script`, `list_scripts`, `remove_script`). It never touches a file it did not write |
| *"Rename the world to Our World"* | The active world is renamed |

## BRUH Sight

BRUH Sight is the app's own plugin. On **Paper and Purpur** it is installed for you and lets the
companion see the live game instead of the saved world files.

| With BRUH Sight | Without it (Vanilla, Fabric, Forge, Folia) |
| --- | --- |
| Where everybody is updates every second | Every five seconds |
| Each player comes with the block and creature under their crosshair, what they hold and carry, what is around them, and the blocks they just placed or broke | Not available |
| Looking at blocks, an edit's undo snapshot and the spyglass read the world as it is now, including builds not saved yet | Read from the saved world |
| The thought bubble and journal are drawn, and the allay goes where the companion is building | Steps show on the action bar |

BRUH Sight changes no block. It answers only the panel, on the machine itself, with a token.

## The world atlas

The app reads the saved world in the background, nearest the players first, and works out:

- **Buildings**, and the **rooms** inside them: floor, free floor space, doors, windows, light,
  furniture, materials, and a guess at what each room is.
- **Roads** between buildings.
- Names from **signs**.

This is how *"put a couch in this room"* works without coordinates.

## Use the same lane in your own automations

The companion uses public events and services, and your automations can use them too. The app
tells Home Assistant what happens (`bruh_minecraft_chat`, `_join`, `_leave`, `_death`,
`_advancement`, `_place`, `_answer`, `_point`) and does what it is asked (`companion_say`,
`ask_choice`, `companion_build`, `undo_action` and more). See
[Home Assistant Integration](/bruh-minecraft/home-assistant/#game-events).
