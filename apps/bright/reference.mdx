## Options

Set these on the app's **Configuration** tab.

| Option | Default | What it does |
| --- | --- | --- |
| `music_folder` | `/media/music` | Where your music lives, under `/media`. Scanned all the way down. |
| `additional_music_folders` | `[]` | More folders to scan, one per line, e.g. `/media/parties`. Must be under `/media`. Folders ticked in the Library tab are added to these; neither replaces the other. Overlapping folders cost nothing. |
| `director_mode` | `auto` | `auto`: Claude through brAIn when available, the built-in director otherwise. `algorithmic`: never call Claude. `claude`: Claude only, and fail instead of falling back. |
| `director_model` | `opus` | The Claude model for writing, revising and inventing shows and effects. Any tier alias (`opus`, `sonnet`) or model id brAIn's login can run. |
| `enable_ha_integration` | `true` | Deploy the `bright` integration and its bridge: the services and the show-status sensor. Off, the panel still works but nothing in Home Assistant can drive it. |
| `log_level` | `info` | `trace`, `debug`, `info`, `notice`, `warning`, `error` or `fatal`. Use `debug` when diagnosing. |

<Aside title="Music outside /media">
Home Assistant only serves a speaker files from its media folder. If your music lives elsewhere,
point Home Assistant's own `media_dirs` at it, and keep one entry pointing at `/media`, where
BRight writes its click track.
</Aside>

## Services

A service that cannot do what you asked fails with the reason. *"no analyzed tracks in
/media/music — run the Library tab first"* appears in the automation trace.

| Service | What it does |
| --- | --- |
| [`bright.party_mode`](#brightparty_mode) | Plays every analysed track, each with its own show |
| [`bright.start_party`](#brightstart_party) | Starts a saved set by name |
| [`bright.start_show`](#brightstart_show) | Plays one track's show |
| [`bright.stop_show`](#brightstop_show) | Stops and restores the room, or calls a scene |
| [`bright.get_status`](#brightget_status) | Returns what is playing, the saved sets and the ready tracks |
| [`bright.import_show`](#brightimport_show) | Loads an edited show file |

```yaml
automation:
  - alias: "Start party mode"
    triggers:
      - trigger: conversation
        command: "start party mode"
    actions:
      - action: bright.party_mode
        data:
          media_player: media_player.living_room
```

### `bright.party_mode`

Plays every analysed track, each with its own show.

| Field | Required | Meaning |
| --- | --- | --- |
| `media_player` | no | Defaults to the most recently calibrated speaker |
| `folder` | no | One folder under `/media`; defaults to every scanned folder |
| `party` | no | A saved set's name; its settings fill in anything not given here |
| `tracks` | no | Exact track hashes, in play order; replaces the folder scan |
| `end_scene` | no | A scene to call when it stops, instead of restoring the lights |
| `shuffle` | no | `false` plays the folder in order |

### `bright.start_party`

Starts a saved set by name. The name is required, so a typo fails with an error.

| Field | Required | Meaning |
| --- | --- | --- |
| `party` | yes | The saved set's name, as on the Party tab |
| `media_player` | no | Override the set's speaker |
| `end_scene` | no | Override the scene called when it stops |

### `bright.start_show`

Plays one track's show.

| Field | Required | Meaning |
| --- | --- | --- |
| `track` | yes | Path under `/media` (or a track hash) |
| `media_player` | no | Defaults to the most recently calibrated speaker |

### `bright.stop_show`

Stops the show and puts the room back.

| Field | Required | Meaning |
| --- | --- | --- |
| `scene` | no | Call this scene instead of restoring the lights |

With no `scene`, every light returns to its state before the show. If the running party named an
end scene, that scene is used instead.

### `bright.get_status`

Returns what is playing, the saved sets, and the tracks with a show ready, as response data. It
changes nothing.

| Field | Required | Meaning |
| --- | --- | --- |
| `parties_only` | no | `true` answers with what is playing and the saved sets (each with its speaker and song count) without scanning the library, which is much faster |

### `bright.import_show`

Makes an edited file in `/config/.bright/shows/` the show BRight plays for that track, the same
as **Reload from file** in the panel. The previous show is kept as a version.

| Field | Required | Meaning |
| --- | --- | --- |
| `track` | yes | The file's name in `/config/.bright/shows/`, or the track's hash |

Invalid JSON is refused with the line it broke on. A script that will not compile is refused with
the reason. Either way, the show that was playing stays.

## Entity

| Entity | State | Attributes worth keying on |
| --- | --- | --- |
| `sensor.bright_show_status` | What BRight is doing (`idle` when nothing runs); a show that failed to start reports `error` rather than claiming to run | `active` (a run is in progress), `lights_busy` (cues still going out), `track`, `media_player`, `position_s`, `party` (the running set), `queue_left`, `cues_sent` / `cues_total`, `parties` (every saved set's name), `playback_warning`, `error` |

Key dashboards and automations on the attributes, not the state string.

## brAIn's tools

With [brAIn](/brain/) installed, two tools drive BRight through these services:

| Tool | What it does |
| --- | --- |
| `bright_status` | Read-only: what is playing, the saved sets, and the tracks with a show ready. Track titles come from the files' own tags and are treated as untrusted. |
| `bright_show` | `party` (a saved set by name, or party mode), `track` (one track's show), `stop` (put the room back, or call a scene), `import` (load an edited show file), with optional `media_player` and `scene` |

A voice agent can only name a speaker or scene it can see, and anything on brAIn's protected
entities list is refused. brAIn also runs the Claude director. See
[Choose who writes the show](/bright/shows/#choose-who-writes-the-show).

## Where BRight keeps things

| Path | What |
| --- | --- |
| `/media/<your folders>` | Your music. BRight only ever reads it. |
| `/media/bright/calibration.wav` | The click track, regenerated when missing |
| `/config/.bright/` | The folder the integration and the app talk through |
| `/config/.bright/shows/` | Every show script, mirrored where you can edit it, with `README.md` and `EFFECTS.md` |
| `/config/custom_components/bright/` | The companion integration, deployed at startup |
| `/data/shows/<hash>/` | Per-track analysis, scripts and compiled shows. Excluded from backups, because they can be rebuilt |
| `/data/calibration/` | One profile per speaker |
| `/data/light-map.json` | The lights, their roles, zones and positions |
| `/data/music-folders.json` | Folders ticked in the Library tab |
| `/data/effect-presets.json` | Saved effects |
| `/data/parties.json` | Saved sets |

BRight never changes your Home Assistant configuration, and restarting the app is always safe.

## Networking

| | |
| --- | --- |
| **Host networking** | BRight runs with `host_network: true`, because LIFX discovery is a UDP broadcast on port 56700 and a bridged container never hears the replies |
| **Panel port** | Assigned by the Supervisor, not fixed. The startup log names it: `Starting BRight panel on 0.0.0.0:<port>` |
| **Who can reach the panel** | Only Home Assistant itself (the Supervisor's network and loopback, judged by the connection's real address). There is no public endpoint. Open it from the sidebar |
| **Hung panel** | The app checks its own health and restarts a panel that stops answering |

## When nothing plays

**Press Test playback on the Calibrate tab first.** It follows a click track all the way to the
speaker and stops at the first broken step:

| Step | What it means |
| --- | --- |
| **file** | The track (or click track) is not where it should be |
| **media id** | Home Assistant will not resolve the media-source link. Often a custom `media_dirs` |
| **host** | The speaker cannot reach the address it was given |
| **player** | The entity does not accept `play_media` |
| **command** | The call was refused |
| **playing** | Accepted, but the speaker never started |

### The host step: Chromecast, Google and Nest

**The fix:** under **Settings → System → Network → Internal URL**, set the machine's IP address
(for example `http://192.168.1.50:8123`), or leave it **empty** so Home Assistant uses its own IP.

Home Assistant hands your speaker a URL built from that setting, and the speaker fetches it by
itself. Chromecast, Google and Nest speakers resolve names through Google's public DNS, not your
router's, so they cannot find `http://homeassistant.local:8123`. Nothing plays and nothing errors.
HTTPS with a certificate the speaker cannot verify fails the same silent way.

### The media step

This step fails when you have set `media_dirs` in `configuration.yaml`. BRight finds the right
media source by itself in most cases.

- **You changed `media_dirs` while BRight was running.** Press **Look again** under the test
  result. No restart is needed.
- **None of Home Assistant's media directories is the folder BRight sees as `/media`.** Add one:

```yaml
homeassistant:
  media_dirs:
    local: /media      # BRight writes here; Home Assistant has to serve from here
    nas: /mnt/nas
```

### Other failures

| Symptom | What to do |
| --- | --- |
| *"could not write the click track"* | Check Home Assistant's media folder exists, then restart the app. |
| *"does not accept play_media"* | Some entities look like media players and cannot be sent media: group members, some remotes and TV inputs. Pick another. |
| It plays, but the lights are early or late | That is calibration. Run **Play clicks & listen** again, or use the nudge under **Stored profiles** (negative moves the show earlier). |
| No bulbs discovered | The bulbs must be on the same subnet as Home Assistant. Some managed switches and mesh systems drop broadcasts between bands or VLANs. |
| *"that bulb has not been discovered — run Lab discovery first"* | Press **Discover bulbs** in the Lab, place the bulbs on the Light Map, and build the show again. |
| *"track not analyzed — run the Library tab first"* | Press **Analyze new tracks** in the Library. Shows compile from the analysis. |
| A track fails to analyse | The reason is reported per file and the folder carries on. Corrupt, empty and undecodable files are the usual causes. |
| Claude never writes the show | Press **Check Claude** on the Shows tab. brAIn must be installed and running. With `director_mode: auto`, BRight uses the built-in director instead without an error. |
| Install blocked: *"no host internet connection"* | That is the Supervisor's connectivity check, usually DNS (often a DNS add-on that is down). `ha resolution info` names the reason; `ha dns reset && ha dns restart` then `ha supervisor reload` usually fixes it. |
