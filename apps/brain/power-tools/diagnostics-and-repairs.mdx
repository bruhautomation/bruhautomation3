Ask brAIn what is quietly broken after a rename or a removed integration, and have it flag things in **Settings → System → Repairs**.

## Ask brAIn

```text
Do any of my automations still reference entities that don't exist?
Put a repair issue up when the front door lock battery is low.
The lock battery is replaced. Clear that repair issue.
```

## What brAIn can do

Every service is admin-only. Call one from **Developer tools → Actions**, a script or an automation, or ask brAIn. \* marks a required field, and `[]` marks a field that takes one value or a list.

| Service | What it does | Fields |
| --- | --- | --- |
| `brain.find_orphaned_references` | Scan every automation, script and scene for entities Home Assistant does not know: renamed, deleted or mistyped. Returns the findings. With `create_issue: true` it also lists them in Repairs. It never changes anything. | `create_issue` |
| `brain.create_repair_issue` | Create an issue in Repairs. `severity` is `critical`, `error` or `warning` (default). `persistent` keeps it across restarts. Give an `issue_id` to remove or replace it later, or one is generated. Returns the `issue_id`. | `title`\*, `description`\*, `severity`, `persistent`, `issue_id` |
| `brain.remove_repair_issue` | Remove an issue by the `issue_id` it was created with. | `issue_id`\* |

brAIn's own findings show up in Repairs too, with their answer buttons. See [Events and entities](/brain/automations/#events-and-entities).

## Examples

```yaml title="Find broken references and list them in Repairs"
action: brain.find_orphaned_references
data:
  create_issue: true
response_variable: findings
```

```yaml title="Raise an issue, then clear it"
- action: brain.create_repair_issue
  data:
    title: "Low battery: front door lock"
    description: "The front door lock reported 8% battery. Replace soon."
    severity: warning
    issue_id: front_lock_battery
- action: brain.remove_repair_issue
  data:
    issue_id: front_lock_battery
```
