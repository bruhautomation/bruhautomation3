Ask brAIn to rename, switch off or remove a device, and to reload, disable or remove an integration.

## Ask brAIn

```text
The Hue integration is acting up. Reload it.
Rename that Shelly device to "Kitchen Ceiling Light".
Disable the old motion sensor I unplugged.
That old thermostat is gone. Show me what deleting its device would take with it, then do it.
Are there devices left behind by integrations I removed? Clean them up.
I've sold the Sonos speakers. How much goes if I remove that integration?
```

brAIn confirms with you before it disables or deletes a device or an integration.

## What brAIn can do

Every service is admin-only. Call one from **Developer tools → Actions**, a script or an automation, or ask brAIn. \* marks a required field, and `[]` marks a field that takes one value or a list.

### Devices

| Service | What it does | Fields |
| --- | --- | --- |
| `brain.rename_device` | Set the name you see for a device. | `device_id`\*, `name`\* |
| `brain.enable_device` | Enable disabled devices, and their parent hub if that was disabled too. | `device_id[]`\* |
| `brain.disable_device` | Disable devices and all their entities. A parent hub is disabled once none of its children remain enabled. | `device_id[]`\* |
| `brain.delete_device` | Remove devices and their entities from the registry. Returns each device's name, entities, child devices and `live_config_entries`. `dry_run: true` shows that without deleting. | `device_id[]`\*, `dry_run` |
| `brain.delete_orphaned_devices` | Remove devices no loaded integration claims any more. **Reports only** unless you pass `dry_run: false`. With `device_id`, each one is re-checked and anything still claimed is skipped and reported under `skipped_not_orphaned`. | `dry_run`, `device_id[]` |

### Integrations

| Service | What it does | Fields |
| --- | --- | --- |
| `brain.reload_integration` | Reload integration entries, like pressing **Reload** on the integration page. | `config_entry_id[]`\* |
| `brain.enable_integration` | Enable disabled integration entries. | `config_entry_id[]`\* |
| `brain.disable_integration` | Disable integration entries and everything they provide. `dry_run: true` lists the entries and entity counts. | `config_entry_id[]`\*, `dry_run` |
| `brain.delete_integration` | Remove integration entries with their devices and entities. Returns each entry's domain and title and how many entities and devices go with it. After a real removal, `require_restart` says whether Home Assistant needs a restart. | `config_entry_id[]`\*, `dry_run` |

<Aside type="caution">
`delete_integration` cannot be undone. `disable_integration` can. A deleted device that its integration still provides comes back on the next reload; `live_config_entries` in the preview tells you so before you delete.
</Aside>

brAIn cannot **add** an integration. Setup forms are interactive, so brAIn takes you to the screen and you click.

## Examples

```yaml title="Reload a stuck integration"
action: brain.reload_integration
data:
  config_entry_id: 1234abcd5678efgh
```

```yaml title="Preview a device delete, then do it"
- action: brain.delete_device
  data:
    device_id:
      - a1b2c3d4e5f6
    dry_run: true
  response_variable: going
- action: brain.delete_device
  data:
    device_id:
      - a1b2c3d4e5f6
```

```yaml title="Review orphaned devices, then delete the ones you checked"
- action: brain.delete_orphaned_devices   # reports only
  response_variable: orphans
- action: brain.delete_orphaned_devices
  data:
    dry_run: false
    device_id:
      - a1b2c3d4e5f6
```

```yaml title="See how much an integration takes with it"
action: brain.delete_integration
data:
  config_entry_id: 1234abcd5678efgh
  dry_run: true
response_variable: going
```
