Ask brAIn for a toggle, a slider, a dropdown or a timer, and it creates the helper together with the automation that uses it.

## Ask brAIn

```text
Build me a manual heating override: a target-temperature slider and a toggle to turn it on.
Add a Guest Mode toggle and make the hallway motion light respect it.
Make a 45-minute laundry timer.
Clean up the test helpers I made last month.
```

## What brAIn can do

Every service is admin-only. Call one from **Developer tools → Actions**, a script or an automation, or ask brAIn. \* marks a required field, and `[]` marks a field that takes one value or a list.

| Service | What it does | Fields |
| --- | --- | --- |
| `brain.create_helper` | Create a helper. `helper_type` is `input_boolean`, `input_number`, `input_select`, `input_text`, `input_datetime`, `counter`, `timer` or `schedule`. Returns the new helper's id and `entity_id`. | `helper_type`\*, `name`\*, `options` |
| `brain.delete_helper` | Delete helpers that were made in the UI. `dry_run: true` lists what would go. | `entity_id[]`\*, `dry_run` |

`options` holds the settings for that type, checked the way the UI checks them:

| Type | Typical `options` |
| --- | --- |
| `input_number` | `min`, `max`, `step`, `unit_of_measurement` |
| `input_select` | `options` (the list of choices) |
| `input_datetime` | `has_date`, `has_time` |
| `timer` | `duration` |
| `schedule` | weekday time blocks |

Helpers defined in YAML are refused by these services. brAIn edits the YAML file for those instead.

## Examples

```yaml title="A heating-target slider"
action: brain.create_helper
data:
  helper_type: input_number
  name: Heating Target
  options:
    min: 15
    max: 25
    step: 0.5
    unit_of_measurement: °C
response_variable: helper   # helper.entity_id
```

```yaml title="Delete a helper"
action: brain.delete_helper
data:
  entity_id:
    - input_boolean.old_test_toggle
```

To change the members of a group helper, see [`set_group_members`](/brain/power-tools/system/#integrations-groups-users-and-dashboards).
