The built-in MCP server gives Claude **120 tools** for reading and changing your live Home Assistant. You never call them yourself. You ask, and Claude picks the tool:

```text
You:     "Why is the hallway light on?"
Claude:  explain_change(entity_id="light.hallway")
         → turned on 19:42 by automation "Hallway motion", triggered by
           binary_sensor.hallway_motion

You:     "Turn it off and dim the kitchen to 30%"
Claude:  control_light(entity_id="light.hallway", action="turn_off")
         control_light(entity_id="light.kitchen", action="turn_on", brightness_pct=30)
```

These tools are Claude's only route to the live home, so protected entities, Blocked services and voice limits are enforced in one place ([how the layers fit](/brain/how-brain-controls-ha/)). `brain doctor` verifies every tool on your install.

## Who may use what

The **Who** column in every table uses these marks:

| Mark | Meaning |
|---|---|
| **read** | Open to unattended runs: scheduled insight cards, the Resident's investigations, study sessions, follow-up looks. Every tool without this mark is explicitly denied to them. |
| **not on voice** | Not offered to a voice agent at the *Voice assistant* level. |
| **exposed only** | On a *Voice assistant* agent, answers only about an entity that is named and exposed to Assist. |
| — | Acts on the house. Open to the chat, the terminal and a [Plan](/brain/needs-you/) run you approved, through the checks below. |

Voice agents set to *Whole house* or *Full admin* are not narrowed ([voice](/brain/voice/)). The chat, the terminal and an approved Plan run can use everything.

## Read automations and scripts

Traces are read live from Home Assistant, so UI-made automations, package automations and runs since the last restart are all visible.

| Tool | What it does | Who |
|------|--------------|-----|
| `get_automations` | Automations with their status and config id | read · not on voice |
| `get_automation_trace` | Why an automation or script did or did not do something: recent runs, how often a condition stopped it, and one run step by step | read · not on voice |
| `get_automation_config` | The definition of any automation or script: UI-made, YAML or package | read · not on voice |
| `search_related` | What a script or scene touches, what uses an entity, what is in an area. The same answer as Home Assistant's Related tab | read · not on voice |

| `room_physics` | A room's heat-loss and gain rates, its time constant, and how long it takes to warm | read · not on voice |
| `appliance_status` | Whether a washer, dryer or dishwasher is idle, running or finished, by its measured power shape | read · exposed only |
| `house_rhythm` | When the house gets up and settles, weekdays and weekends apart | read |
| `door_habits` | How much of each hour of the week a door, window, lock or cover is usually open | read · exposed only |
| `habits` | What you do by hand with an entity often enough to be a habit, with the overrides against it | read · exposed only |
| `simulate_automation` | Replay an automation config over the recorder's last weeks and grade it against what you did. Calls nothing | read · not on voice |
| `recall` | Search the [facts store](/brain/memory/): what brAIn knows, who taught it and when | read |

## Change what a device shows as

Ask in the chat or the terminal: *"show the back door sensor as a door"*, *"show the fan plug as a fan"*. Each tool is a [Power Tool](/brain/power-tools/entities/#what-a-device-shows-as) called through `call_service`, so every check applies.

| Tool | What it does | Who |
|------|--------------|-----|
| `set_device_class` | Home Assistant's *Show as*: a binary sensor as a door, window, garage door, motion or leak sensor; a cover as a garage, blind, shutter, curtain or gate; a switch as an outlet. Empty restores the integration's own | not on voice |
| `show_switch_as` | Show a switch (a smart plug running a fan or lamp) as a light, fan, lock, cover, siren or valve. Returns the new entity id | not on voice |
| `stop_showing_switch_as` | Undo it. Lists what used the entity that goes away, with a dry run | not on voice |
| `set_sensor_display` | A sensor's decimal places and, where Home Assistant can convert it, its unit (°C to °F, W to kW) | not on voice |

A smoke, gas, CO or leak sensor keeps its type unless you say yes, because brAIn's [safety alerts](/brain/safety/) go by it.

## The checks every acting tool passes

- **One chokepoint.** Every tool that acts goes through `call_service`, so per-agent **Blocked services** and **protected entities** cover all of them. `homeassistant.*` meta-calls are resolved to their targets' domains. A target that cannot be resolved is refused. `fire_event` is refused while anything is protected.
- **The whole request is read.** An entity named anywhere in a call is checked: a scene's `entities` map, `snapshot_entities`, `group_members`, a speaker field, a script variable. Running a scene, script or automation is checked by what Home Assistant says it references.
- **Voice is scoped by service as well as entity.** On a *Voice assistant* agent, a request naming no entity is refused unless it is a notification or a BRUH play service. A request naming entities may use only those entities' own services. `update.install` is always refused.
- **Unattended runs have two lists.** An allow-list of the **read** tools and a deny-list of every other tool. Every tool is in exactly one, so a new acting tool cannot reach an unattended run.
- **The action gate.** In the chat and the terminal, a gate in front of every acting tool decides from your own words, never from text brAIn read. With *Let brAIn act without asking* on it stops asking; the tripwire, the deny-list, your house rules and protected entities still decide ([reference](/brain/reference/#let-brain-act-without-asking)).
- **Outside text is data.** A media title, a calendar event or a logbook message is handed to Claude marked as data, not instructions.
- **Power Tools check again.** `brain.*` services enforce admin access and validate ids inside the service, whoever calls.

The full order of checks: [What every action passes](/brain/how-brain-controls-ha/#what-every-action-passes).

## Generated context

With `auto_generate_context` on (the default), brAIn rewrites `/config/CLAUDE.md` at startup: your entities by domain, rooms, automations and their states, add-ons, integrations, a directory guide, and how to use the MCP tools and Power Tools. Claude reads it at the start of every session, so it already knows what `sensor.lumi_lumi_weather_temperature_3` is doing in your kitchen. Regenerate it any time with `ha context`.
