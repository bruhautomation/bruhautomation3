title: Overnight Self-Healing
description: Three repairs brAIn may make while you sleep. It starts an add-on that should be running, pings a dead Z-Wave node and reloads an integration that failed to set up. Off by default, at most three a night, and reported in the morning brief.

import { Aside, Steps } from '@astrojs/starlight/components';

With self-healing on, brAIn makes up to three small repairs a night while the house is
asleep, and the morning brief tells you what it did:

> *brAIn started the Mosquitto broker add-on at 03:10; it is working now.*

It is **off by default**. It is the only thing brAIn does to your house without a press
from you, so it is also the narrowest.

## What it repairs

Each repair answers a problem the [house checks](/brain/checks/) already found.

| The problem | What brAIn does | Why it is safe unattended |
| --- | --- | --- |
| An add-on set to start at boot is not running | **Starts it**, through the Supervisor | It was meant to be running. This is what boot would have done. |
| A Z-Wave node the controller has marked dead | **Pings it** | The controller re-marks the node if it answers. Nothing in the house moves. |
| An integration failed to set up | **Reloads it** | Reloading something already broken cannot make it more broken. |

That is the complete list, and it cannot be extended.

<Aside type="caution" title="What it never does">
- **No power-cycling.** A plug switched off and on again may have a freezer behind it.
- **No restart** of Home Assistant or of brAIn.
- **No Claude run.** No model chooses what to repair.
- **Nothing on a protected entity, area or device.**
- **No add-on in an error state.** It already failed to start. That needs you and its log.
- **No add-on set to start manually.** You stopped it on purpose.
- **Nothing you have already answered.** Only open problems. A card you sent to be fixed,
  snoozed, ignored or dismissed is left alone.
</Aside>

## Turn it on

<Steps>

1. Open the brAIn app's **Configuration** tab in Home Assistant.
2. Switch on **Fix three things overnight** (`self_healing`).
3. Set your quiet hours, if you have not. See [Notifications](/brain/notifications/).

</Steps>

## When it runs

Once a night, in the first window that applies:

| You have | It runs |
| --- | --- |
| **Quiet hours set** | Inside your quiet hours. |
| **No quiet hours, but brAIn has [measured](/brain/measurements/) when your house settles** | An hour after that settle time, in a 45-minute window. |
| **Neither** | Not at all. **⚙ → Diagnostics** says so. |

There is no button to run a pass on demand. A night runs from midday to midday, so 23:40
and 03:10 count as the same night.

## The limits

| Limit | Detail |
| --- | --- |
| **Three repairs a night** | Oldest problem first. A house with nine things broken needs a person. |
| **One attempt per problem per night** | Recorded after every attempt, so a restart at 3am does not repeat one. A failed call is not retried that night. |
| **Protected means untouched** | A ping reaches the whole device, so every entity on that Z-Wave device is checked against `protected_entities`, not only the one named. |
| **Cannot tell, does not act** | If brAIn cannot work out which entities a repair would touch and your protected list is not empty, it skips. |
| **Could not look, does not act** | If the Supervisor or Home Assistant did not answer this pass, nothing is repaired from that reading. |

## See what it did

**The morning brief** reports every repair and whether it held. A repair made overnight is
itself a reason to send that morning's brief.

> *brAIn pinged the Z-Wave node Back door sensor at 03:11; it has not cleared yet.*
>
> *brAIn tried to fix something overnight and could not: it reloaded the Hue integration at
> 03:10 — the call failed.*

brAIn does not check its own call. The Supervisor accepting a request is not proof that an
add-on is running. The proof is the next house-checks pass: the problem clears, or it does
not, and the brief says which.

| Where | What |
| --- | --- |
| **⚙ → Diagnostics**, **Overnight repairs** | Off or on, how many were tried last night, how many were skipped, any that failed, and **Not running because** when it has no window. |
| **The run journal** | Every attempt as `healed`, `heal_failed` or `heal_skipped`, with the reason for each skip. |
| **`brain report`** | Both of the above, bundled for a bug report. |

## When the same fault keeps coming back

A fault repaired every night is a fault being hidden. So brAIn counts repairs across
nights, per add-on, node or integration.

After the **third repair of the same thing in 14 days**, brAIn stops repairing it and files
a problem on [Needs you](/brain/needs-you/) saying the fault keeps returning. The card
quotes the log lines that say why:

- For an add-on, that add-on's own log.
- For an integration or a Z-Wave node, Home Assistant's error log, filtered to that
  integration.

Error and warning lines come first, and anything shaped like a token is removed. If brAIn
could not read the log, the card says so. Before that point, a repeat repair is reported in
the brief as a repeat, not as new.
