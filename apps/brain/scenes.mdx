Ask for scenes for a room and brAIn composes four moods for it: morning, day, evening and
night. You see every light in every mood before anything is written.

![A Suggestion card marked Scenes, "Four scenes for the Living room". Under Details, four rows named Bright start, Daylight, Wind down and Night path, each with one colour swatch per light: pale cool swatches for morning, warm orange for evening, and at night a single dim swatch with the rest as empty outlines. The lights are named underneath, and a line reads "Skipped: protected — Bookshelf plug". Presses: Apply, Snooze, Ignore](./images/act-scenes.webp)

## Design scenes for a room

<Steps>

1. Ask, naming the room: *"Design my evening for the living room"* or *"Set up scenes for
   the kitchen"*. Type it in the *Ask or tell the house* line on [Morph](/brain/morph/), or
   ask in [Ask](/brain/terminal/), where the **Design lighting scenes for a room** starter
   fills the box for you to finish with the room.
2. brAIn answers straight away. Either it is designing them, or it tells you why it cannot
   for that room.
3. A card marked **Scenes** lands on **Insights → Needs you** a moment later.
4. Open **Details** to see the swatches, then press **Apply**.

</Steps>

Apply writes all the scenes at once to `scenes.yaml`, reloads, and waits for every scene to
appear in Home Assistant. If any step fails the file is put back and the card says what was
tried. The toast offers **Undo**, and `brain undo` works later. The full path is on
[Suggestions](/brain/proposals/#saying-yes-and-taking-it-back).

With *Act* or *No limits* set in ⚙ → Permissions, scenes you ask for are written at once,
with the same checks and the same Undo.

## Read the card

| On the card | Meaning |
| --- | --- |
| **A swatch per light per mood** | The colour and level that bulb will hold in that scene. |
| **An empty outline** | That light is off in that scene. |
| **The names under the strip** | Which light each swatch is, left to right. |
| **Skipped: protected** | A light on your `protected_entities` list. brAIn knows it is there and will not set it. |

There is no replay and no trial week for scenes. Nothing in your history set them, so the
swatches are the evidence.

## The four moods

| Mood | Colour temperature | Brightness | Lights on |
| --- | --- | --- | --- |
| **Morning** | 5000 K, cool | 80% | All |
| **Day** | 4000 K, neutral | 100% | All |
| **Evening** | 2400 K, warm | 45% | All |
| **Night** | 2000 K | 10% | Only the night lights |

The numbers are fixed, so the same room gets the same scenes every time you ask.

**Night lights.** brAIn uses what it has [read about each device](/brain/checks/), in any
language. Where it is not sure, it goes by the name: *night*, *bedside*, *hall* or *landing*
as whole words. A room with no such light goes fully dark at night.

**Names.** brAIn asks Claude for four names you would say out loud, each under 24
characters. This is the only thing a model decides. If that run fails, the scenes are called
Morning, Day, Evening and Night. Names follow the pattern your existing scenes already use.

**Moods you already have.** If the room has a scene for a mood, brAIn does not make a
second one. It offers only the missing moods, and none if all four exist.

## What each bulb is told

brAIn reads each light's `supported_color_modes` and sets the most it can take.

| The bulb takes | The scene sets |
| --- | --- |
| A colour temperature | The mood's kelvin and a brightness |
| Colour but no temperature | The nearest colour to that kelvin, and a brightness |
| Brightness only | The brightness |
| On and off only, or modes brAIn could not read | On or off |

The card's first lines say how many of the room's lights fall into each row.

<Aside type="note" title="In scenes.yaml, brightness is 0–255">
The card speaks in percent. The file stores `brightness` from 0 to 255, with
`color_temp_kelvin` or `rgb_color`, because those are the values Home Assistant restores
from a scene.
</Aside>

## Rooms brAIn will not design for

The refusal comes back as soon as you ask.

| Refusal | Why |
| --- | --- |
| **Fewer than two lights brAIn can set** | Four scenes over one bulb are the same scene. If the rest are protected, the refusal says so. |
| **More than 40 lights** | That is a floor, not a room. Split it into areas and ask again. |
| **Every mood already has a scene** | There is nothing to add. |
| **These scenes were already offered** | The card is waiting on Needs you. |

Apply is refused, with the reason on the card, when:

- `configuration.yaml` has no `scene: !include scenes.yaml` line. The refusal names the line.
- `scenes.yaml` is not a list of scenes. An empty file, a missing one, or one holding only
  comments is fine.
- A scene with the same id or name is already in the file.
- A scene would set a protected light.

## Add the schedule

Once all four scenes exist, brAIn offers a second suggestion: one automation that moves the
room through them.

![A Suggestion card "Move the Living room through its four scenes": "Morning at 06:50 and night at 23:10 are measured — that is when this house actually gets up and settles; 11:00 and 18:30 are fixed guesses you can change." Presses: Apply, Snooze, Ignore and a ⋯ menu](./images/act-scene-schedule.webp)

| Mood | When | If brAIn has not measured enough days |
| --- | --- | --- |
| **Morning** | Your house's [measured](/brain/measurements/) wake time | 07:00 |
| **Day** | 11:00, a fixed guess | 11:00 |
| **Evening** | 18:30, a fixed guess | 18:30 |
| **Night** | Your house's measured settle time | 22:30 |

The card says which times are measured and which are defaults. All four are yours to
change once the automation is in your file.

The schedule is an ordinary automation. You can
[try it for a week](/brain/proposals/#try-it-for-a-week-first) before applying it. It is
offered whenever the four scenes are in `scenes.yaml`, including when you pasted them in
yourself.

## Where to see it

| Where | What |
| --- | --- |
| **Insights → Needs you** | The card, with a **Scenes** pill. |
| **⚙ → Diagnostics** | How many sets have been designed and how many asks were refused. |
| `GET /api/scenes/areas` | The rooms that qualify, and how many lights each has. |
