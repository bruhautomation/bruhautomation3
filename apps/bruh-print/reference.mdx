Everything you can set, call and read in BRUH Print, and what to do when a label comes out wrong.

## Services

Every service answers with what happened (`printed`, `side`, `notes`, `status`), so a script can
branch on it. A refused print fails with the reason.

```yaml
# One word, as big as fits
action: bruh_print.print_text
data:
  text: Spare batteries
  copies: 2
```

```yaml
# Fill in a template
action: bruh_print.print_template
data:
  template: Freezer bag
  fields: {contents: Chili}
```

```yaml
# Tell it a new roll went in
action: bruh_print.set_roll
data: {side: left, stock: edcc-082wh, remaining: 1000}
```

| Service | Fields | What it does |
| --- | --- | --- |
| `bruh_print.print_text` | `text`\*, `stock`, `copies`, `font`, `rotate`, `uppercase` | Fits a word or a line to a label as large as it will go and prints it. Line breaks are kept. With no `stock`, it uses the one loaded stock, or else the label text prints on. |
| `bruh_print.print_template` | `template`\*, `fields`, `copies` | Fills in a saved [template](/bruh-print/templates/) and prints it on the label it was made for. An empty field refuses. |
| `bruh_print.print_label` | `label`\*, `copies` | Prints a complete [label document](/bruh-print/designer/#the-label-document) |
| `bruh_print.reprint` | `entry`, `copies` | Prints something from History again, exactly as it came out. No `entry` reprints the most recent. |
| `bruh_print.set_roll` | `side`\*, `stock`\*, `remaining` | Records which labels are in a roll (`left` or `right`). `remaining` defaults to a full roll. |
| `bruh_print.print_test` | `stock` | Prints a check label: a frame around everything the roll can print on |
| `bruh_print.choose_label` | `stock`\* | Sets which loaded label plain text prints on. Prints nothing. |
| `bruh_print.get_status` | | Returns the printer, what is in each roll, the templates with their fields and whether their stock is loaded, and which stock text prints on. Prints nothing. |

\* required. `copies` runs from 1 to 500. `stock` is the id shown beside each stock on the Printer
tab, such as `edcc-082wh`.

## Entities

| Entity | State | Attributes worth knowing |
| --- | --- | --- |
| `sensor.bruh_print_printer` | Model name | `two_rolls`, `dots_across`, `serial`, `text_prints_on`, `templates` |
| `sensor.bruh_print_left_roll` | Estimated labels left | `stock_name`, `size`, `loaded`. Unknown while counting is off. |
| `sensor.bruh_print_right_roll` | Estimated labels left | Unavailable on a one-roll printer |
| `sensor.bruh_print_last_label` | What came out last | `entry_id`, which you can pass to `reprint` |
| `sensor.bruh_print_printed_today` | Count | |
| `binary_sensor.bruh_print_problem` | `on` means trouble | `reason` says what, in words |

When the app stops, the entities stay available and report it, so `reason` is still readable.

```yaml
automation:
  - alias: "Label printer needs attention"
    triggers:
      - trigger: state
        entity_id: binary_sensor.bruh_print_problem
        to: "on"
    actions:
      - action: notify.notify
        data:
          message: "Label printer: {{ state_attr('binary_sensor.bruh_print_problem', 'reason') }}"
```

## brAIn's tools

With [brAIn](/brain/) installed, you can ask for a label by voice or in chat. brAIn uses two tools:

| Tool | What it does |
| --- | --- |
| `label_printer_status` | Reads the printer, what is loaded in each roll, the saved templates and their fields, and the last few labels. Changes nothing. |
| `print_label` | Prints text fitted as large as it will go, or a saved template with its fields. `copies` defaults to 1. |

brAIn reads the status first, so it names a stock and a template that exist.

<Aside type="caution" title="Voice prints at most 10 copies">
A voice assistant is refused above 10 copies at once, because a misheard "two hundred" is a whole
roll.
</Aside>

## Options

Set these on the app's **Configuration** tab.

| Option | Default | What it does |
| --- | --- | --- |
| `enable_ha_integration` | `true` | Installs the `bruh_print` integration: the services, the sensors and the data the card reads. Turn it off if you only print from the panel. |
| `install_lovelace_card` | `true` | Copies the card into `/config/www/bruh_print` and registers it. Turning it off stops the registration only, so cards already on a dashboard keep working. |
| `default_stock` | `edcc-082wh` | The label a new design starts on, and what a text print assumes when it names none |
| `enforce_stock` | `true` | Refuses a label whose stock is not in the target roll. Leave it on. |
| `log_level` | `info` | `trace` to `fatal`. Successful status polls are logged only at `debug`. |

`default_stock` and `enforce_stock` only set the panel's starting values on first run. After that,
change them in the panel. The print quality settings are on the
[Printer tab](/bruh-print/rolls/#set-print-quality).

## Supported printers

| Printer | Notes |
| --- | --- |
| LabelWriter 400, 450, 450 Turbo, 450 DUO, 4XL, Wireless | One roll |
| LabelWriter 450 Twin Turbo | Two rolls, [chosen for you](/bruh-print/rolls/#use-two-rolls-on-a-twin-turbo) |
| LabelWriter 550, 550 Turbo, 5XL | Read an RFID tag on the roll and refuse labels without one. Nothing in software can change that. |
| Any other DYMO on USB | Driven as a 450. A second roll is detected from the device's own product name. |

The printer needs its own power supply and a USB cable that carries data.

## Troubleshooting

### Nothing prints

| Symptom | What to do |
| --- | --- |
| *"No DYMO printer is on the USB bus."* | Check, in order: the printer's power, a charge-only cable, an unpowered hub. There is no setting to change. |
| *"…is connected but this add-on may not open it."* or *"…is claimed by something else"* | Restart the app. If it persists, another app such as CUPS or a print server has claimed the printer. Two drivers cannot share one LabelWriter. |
| It says it printed and nothing came out | **Printer → Settings → If nothing comes out**. Try the next mode and press **Print a check label**. Please report which mode worked. |
| Nothing prints and there is no error | Check that the roll is seated and the lid is closed, then press **Check paper and lid** |
| **Check paper and lid** says it cannot ask | The printer's USB connection is one-way. Printing is unaffected. **Show connection info** shows what it exposes. |
| **Check paper and lid** got no answer | Normal. A LabelWriter in the middle of a feed, or with older firmware, does not reply. |
| A refusal naming two stocks | The label is for a stock that is not in that roll. Load it and record it on the Printer tab, or pick a loaded label. |

### The label comes out wrong

| Symptom | What to do |
| --- | --- |
| The whole label is rotated, with text off the edge | The stock's two measurements are swapped. **Rename or resize → These are the wrong way round**. |
| The label is the right shape and the words run the wrong way | **Text direction** on the stock's row |
| Everything prints too far down or to one side, by the same amount every time | [Line up this roll](/bruh-print/rolls/#lining-up-a-roll) |
| The label is blank, or half of it is | **Print a check label**. A complete frame means the artwork is outside the printable area, often because the stock is wrong. A missing side means the roll needs lining up. |
| The words sit too close to the edge | Raise the blank border under **Rename or resize** for that stock |
| Print is too light, or labels smudge or curl | **Printer → Settings → Darkness** |

### The dashboard card

| Symptom | What to do |
| --- | --- |
| *"Custom element doesn't exist"* | Restart Home Assistant once. See [Dashboard Card](/bruh-print/card/#fix-a-card-that-shows-nothing-or-cannot-print). |
| The card says it cannot find the sensors | Name the renamed entities in the card. Printing still works. |

## How the printing works

You do not need any of this to print. It explains the behaviour you see.

- **No CUPS and no DYMO driver.** BRUH Print sends the LabelWriter's own raster commands over USB,
  in the same sequence DYMO's CUPS driver has used for twenty years.
- **The preview is the print.** Both come from one bitmap, and nothing is anti-aliased, because a
  thermal head prints dots that are on or off.
- **A 2.25″ label on a 2.24″ head.** The LabelWriter 450's head is 672 dots at 300 dpi. The three
  dot columns it cannot reach are left off the canvas. Scaling the artwork down instead would make
  barcode bars fractional.
- **A run of ten is ten labels.** Copies between the first and last get the short form feed, so
  no blank labels come out between them.
- **Roll, darkness and speed are sent once per job.** The search for the top of the label is sent
  per copy.

## Backups

Stocks, rolls, templates, history and settings are all in `/data` and go into Home Assistant
backups. None of it is a credential, and the app has no login.
