<Release version="0.2.0" latest>
<Changes type="changed">

- **The header lines up with the page**: the title, the CPU, Memory, Load and Up meters and the tabs sit on the same edges as the lists under them.
- **On a phone** the title and meters scroll away with the page and only the tabs stay at the top; an app is three short rows (name and labels, CPU beside memory, then its buttons), and a long name wraps instead of being cut off.
- **Settings** is split into three clear parts — Level 2: show every process, End processes, and Runaway apps — with the Never end these list and its Save button together.
- On the Processes tab, the kind of group (App, Operating system…) lines up with the group's name.
- Spacing, text sizes and corners follow the shared BRUH standard: nothing smaller than 12 px, one height for buttons and fields.

</Changes>
</Release>

<Release version="0.1.4">
<Changes type="fixed">

- CPU and memory numbers line up on every row of the Processes tab, including rows with no End button; the four meter labels sit at the same height.

</Changes>
</Release>

<Release version="0.1.3">
<Changes type="changed">

- **The add-on says when Home Assistant needs a restart, and only then** — when the integration code it loaded differs from what was just installed.

</Changes>
</Release>

<Release version="0.1.2">
<Changes type="security">

- A name sent to the panel can't forge a line in the add-on's log: the app name and action of a Restart or Stop are logged with line breaks and control characters replaced.

</Changes>
</Release>

<Release version="0.1.1">
<Changes type="fixed">

- **Level 2 could not start.** With Protection mode off the add-on shares the machine's process list, so it is no longer process 1, and the base image's start-up program refused to run anywhere else. The add-on now starts its own script directly.
- The Protection mode check uses bashio's new name, and start-up warnings lost their doubled spaces.

</Changes>
</Release>

<Release version="0.1.0">
<Changes type="added">

- **Level 1, apps.** CPU, memory, network and disk for every app, Home Assistant, the Supervisor and its plugins, measured by the Supervisor every few seconds, with a history line per app. Restart, Stop and Start, each asking first and saying what it will cost.
- **Level 2, every process** — off by default; in effect once Protection mode is off. Every process grouped by app, with CPU, memory and command line. The Settings page explains Protection mode and ticks off the three steps.
- **End process** — a second switch, off by default, only for processes inside apps. SIGTERM first; Force end only if it is still running five seconds later. A Never end these list.
- **Runaway apps**, marked in the panel and as a Home Assistant binary sensor. Nothing is stopped automatically.
- **The Home Assistant integration**: CPU, memory, busiest app and its CPU, and the runaway binary sensor.

</Changes>
<Changes type="security">

- The AppArmor profile denies reading any other process's environment or memory, so Level 2 can't see other apps' tokens or passwords.
- The add-on rates 5 in the store, not 6: `host_pid` costs two points whether or not Protection mode lets it take effect.

</Changes>
</Release>

</Changelog>
