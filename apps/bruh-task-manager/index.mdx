BRUH Task Manager is marked **experimental** in the add-on store. Level 1 only reads what
the Supervisor already measures; Level 2 and End process are off until you turn them on.
</Aside>

## What it is

Your Home Assistant box feels slow. The fan is loud. The history graphs lag. Something is
eating the CPU — but Home Assistant's own Hardware page shows one number for the whole
machine, and the add-on store shows a little gauge per app that you have to open one by
one.

**BRUH Task Manager is the Task Manager your PC has, for Home Assistant OS.** It opens in
the sidebar as **Task Manager**, lists every app busiest first with its CPU, memory,
network and disk, a history line for each, and **Restart**, **Stop** and **Start** buttons
that tell you what they will cost before you press them.

## Two levels

<CardGrid>
  <Card title="Level 1 · every app" icon="list-format">
    **On from the moment you install it**, needing nothing from you. Every app, Home
    Assistant, the Supervisor and its plugins, measured by the Supervisor every few seconds
    — the same figures behind Settings → System → Hardware.
  </Card>
  <Card title="Level 2 · every process" icon="magnifier">
    **Off until you turn it on.** Every process on the machine — Home Assistant's Python,
    the ffmpeg it starts for a camera, each app's programs, Docker, the operating system —
    grouped by the app it belongs to. Needs Protection mode off; the Settings tab says
    exactly what that does first.
  </Card>
</CardGrid>

## Highlights

<CardGrid>
  <Card title="Restart with eyes open" icon="warning">
    Every Restart and Stop asks first and says what it will cost: which integrations talk
    to the app (they go unavailable while it is down), whether its sidebar panel stops
    opening, and whether it starts again at boot.
  </Card>
  <Card title="End process, carefully" icon="close">
    A third switch, off by default. Only for processes **inside apps**. It asks the process
    to stop (SIGTERM) and offers **Force end** only if it is still running five seconds
    later. Never offered for Home Assistant, the Supervisor or the operating system.
  </Card>
  <Card title="Runaway apps" icon="rocket">
    An app above a CPU threshold (80%) for long enough (10 minutes) is marked, and a
    **Runaway app** binary sensor turns on for your automations. A backup or an update
    burst doesn't count. Nothing is stopped automatically.
  </Card>
  <Card title="Can't read your secrets" icon="seti:lock">
    Even with Level 2 on, its AppArmor profile denies reading any other process's
    environment or memory — so it can't see other apps' passwords or tokens. It opens no
    port.
  </Card>
</CardGrid>

## Use cases

**"Why is the house slow tonight?"** Open Task Manager: Studio Code Server's extension
host is at 84% — a search you started in the editor hours ago is still indexing. You
switch to **Processes**, open Studio Code Server and **End** that one helper process; the
editor stays up and the machine goes quiet.

**The camera that ate a core.** Level 2 shows an `ffmpeg` under Home Assistant pulling 40%
for one RTSP stream. You don't end it (Home Assistant's own processes are never offered) —
you fix the stream's settings, and watch the line drop.

**The 3 AM runaway.** An app spins at 95% for ten minutes while everyone is asleep. The
**Runaway app** sensor turns on; your automation restarts that app with
`hassio.addon_restart` and sends you a note saying which app and when.

**"Can I stop this, or will something break?"** Press **Stop** on Mosquitto and the
dialog tells you the MQTT integration will show as unavailable, and that it's set to start
at boot. You press **Restart** instead.

**A dashboard of the box.** The integration's **CPU**, **Memory used** and **Busiest app**
sensors go on a wall tablet next to the weather.

## What you need

- **Home Assistant OS** (or Supervised) — the Supervisor is where the figures come from.
  Home Assistant 2023.6 or newer.
- **A 64-bit machine**: `amd64` or `aarch64`.
- For Level 2 only: the willingness to turn **Protection mode off** on this one add-on
  while you look, and back on when you are done.

## Security rating

The add-on store shows this add-on's **security rating as 5**, not 6. That is because it
*asks* for the machine's process list at all (`host_pid`), and it is the same whether
Protection mode is on or off: the Supervisor only grants that view while Protection mode
is off. brAIn's security check knows this, and does not flag Task Manager's Protection
mode as a fault.
