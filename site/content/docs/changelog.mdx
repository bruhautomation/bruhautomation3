<Release version="1.20.0" date="August 14, 2026" latest>

The app docs describe the apps that actually ship again.

<Changes type="added">

- **Thirty-six releases of missing release notes.** The [brAIn changelog](/brain/changelog/) had stopped at 1.14.0 while the add-on shipped 1.27.0 — twenty-nine releases, including the 6/6 security hardening, the chat's permission cards and model picker, per-card cost reporting, and findings that can ring a phone. The [BRUH Minecraft changelog](/bruh-minecraft/changelog/) was seven behind, including its own LAN-gate and AppArmor release. All ported, condensed from the add-ons' own changelogs.
- **The features those releases added are documented where a reader would look for them.** Findings notifications, `brain findings`, memory export/import and the scheduler's *next in 4 h* on brAIn's pages; Featured worlds (Drehmal), world import, the Resource Packs tab and the panel's LAN gate on BRUH Minecraft's — with the two committed-but-unused panel screenshots finally put to work.

</Changes>
<Changes type="fixed">

- **The docs no longer contradict the products.** Guesses are answered on the Findings tab, not Memory; **✕ Wrong** replaced Ignore, and endings have an Undo; insight runs hold read-only tools rather than none; `memory_max_kb` ships at 32 KB, not 8; the usage tracker polls every 30 minutes, not 2; installs are a prebuilt-image pull, not a local build; 14 Minecraft services, not 13; `auto_restart_schedule` takes cron, not a clock time. Dozens more of the same shape, each verified against the shipped add-on rather than the previous sentence.
- **`/brain/reference/#undo` lands on the Undo explainer again** — two headings slugified to the same anchor, and the three pages linking it were sent to a one-row option table instead.
- **`brain.reset_dashboard_config` is documented** — the site described 64 of the 65 Power Tools while claiming 65 in three places.

</Changes>
</Release>

<Release version="1.19.1" date="August 3, 2026">

Page views are counted again — on every page this time.

<Changes type="added">

- **Vercel Web Analytics**, as the one `defer`red script Vercel serves at the edge. It is on all 88 pages, including the landing page and the Minecraft command builder, which are outside Starlight's layout and are exactly the two that a "put it in the docs layout" answer misses. No npm dependency: on a static site with no client router, the `@vercel/analytics` package exists to load this one file. Nothing about the page changes for a reader, and nothing is served anywhere but Vercel.

</Changes>
</Release>

<Release version="1.19.0" date="August 3, 2026">

Thirteen projects gone, and the rough pages now say what's rough about them.

<Changes type="removed">

- **Thirteen projects are gone** — the BLE hub, dog treat dispenser, laser turret, Christmas ornaments, cold air return baffle, dinner bowl rest, duct cap & adapter, folding wall hooks, fridge drawer support, magnetic hook, magnetic ring unlocker, outlet cover and popup key holder. Pages, files and folders, all of it, out of the repo as well as off the site. The [project list](/project-list/) is 51 projects now. The one old URL that pointed at any of them — `/home-projects/3d-prints/magnetic-ring-unlocker/` — has been dropped rather than left redirecting to a page that isn't there, so it 404s once instead of twice.

</Changes>
<Changes type="changed">

- **"Pending write-ups" is "Show drafted write-ups".** The sidebar switch, the notice at the top of a rough page and the project list all use the one word now, and all three say the thing the old wording talked around: a drafted write-up is a first pass, some of it is probably AI-generated slop, and it should be taken with a grain of salt. The files attached to those projects are the real thing and always were — the words are what's being caught up on. Better said up front than worked out by a reader on the third page, who then stops trusting the finished guides too.

</Changes>
</Release>

<Release version="1.17.0" date="August 1, 2026">

Every project in the repo now has a page, and parts that only exist as CAD can be spun on it.

<Changes type="added">

- **A page for every project.** 45 projects had files in the repo and nothing on the site; they have pages now, each with its parts in the 3D viewer and its files ready to download. The [project list](/project-list/) is all 64 of them.
- **CAD gets previewed.** A part that was never exported to STL is tessellated from its STEP file and loaded into the viewer, labelled *from CAD* — so projects that only ever shipped Fusion files can be looked at before you download anything. Previews are approximate where the STEP is exact, so they are shown but never offered as a download.
- **CAD source is listed by name.** Every `.step` and `.f3d` is a download row saying what opens it, instead of a line counting how many are in the folder.

</Changes>
<Changes type="fixed">

- **The sidebar icons were one category out, and Apps had none at all.** They were pinned to sidebar positions in the stylesheet — written when there were three project categories — so adding two slid every glyph one group along (Around the House wore the flask) and pushed the Apps icon off the end. Each category now carries its own icon, the sidebar rules are generated from the sidebar's own running order, and the same glyph draws the card on the front page. Adding a category can't shift them again.

</Changes>
<Changes type="changed">

- **Everything that was in development is live.** The ten in-development guides are published. Where a photo is still to come, the author's placeholder is gone rather than shipped — a page shouldn't tell a reader what its writer still has to do.
- **Workshop & Garage has its own icon** — a hammer. It was sharing the wrench with Around the House, which read as one category cut in half.
- **BRUH Minecraft has a real mark.** It was wearing a gradient plate with an isometric cube on it — no `BR` ligature, no gable, not even the palette. Both apps now use the same lockup as the parent logo, and what tells them apart is how it's drawn: brAIn is smooth throughout, Minecraft is stepped onto a 16u block grid — caps *and* roof, so the whole mark is built to one rule. Nothing anywhere ships the gable on its own any more — it says BRUH, and says nothing about which app you're looking at.

</Changes>
</Release>

<Release version="1.16.0" date="August 1, 2026">

Every project page now ends with the files you came for.

<Changes type="added">

- **Every printable part is in the viewer.** A project page used to preview one hardcoded STL, if any; it now lists every part in `projects/<project>/models/` and lets you spin any of them — buttons for a handful, a picker for the 62 the Cellcube stand has. Each part is a download link with its size beside it, and the project's folder on GitHub is one link away.
- **ESPHome configs are on the page.** If a project has YAML, the whole file is now in the guide with syntax highlighting, a line count, and links to view or download it on GitHub. Long files start folded. Nothing is transcribed by hand — the page reads the file out of the project folder when the site builds, so editing the config on GitHub updates the page.

</Changes>
<Changes type="fixed">

- **Models that sat away from their origin were invisible.** The viewer offset the mesh to centre it but scaled it afterwards, and scale doesn't apply to position — so anything exported out of a Fusion assembly landed off camera and the preview was an empty grid. It centres the geometry now. This is why the tablet mount's keystone plates showed nothing.

</Changes>
<Changes type="changed">

- **The Autodesk viewer links are gone**, along with the hand-written "STL and STEP files are in the GitHub repo" paragraphs they sat next to. The models are on the page.

</Changes>
</Release>

<Release version="1.15.0" date="August 1, 2026">

Projects are sorted by project, and filed by what they're for.

<Changes type="changed">

- **New categories.** Smart Home, Maker and Lab are gone. A project is now filed by what it's *for* — **Home Automation**, **Mounts & Enclosures**, **Around the House**, **Workshop & Garage**, **Lab & Science** — and how it was built is a tag (`3d-print`, `esphome`, `arduino`, `laser-cut`). The old scheme mixed the two axes, which is how one bucket ended up holding a doorknob cover, a router sled and a lab tube rack.
- **Every project has one folder.** The guide, the photos, the print files, the CAD source and the firmware now live together in `projects/<project>/`, instead of being split across four top-level directories. The [project list](/project-list/) is generated from those folders, so it lists all of them — the forty-odd that are files and notes as well as the ones with a written guide — and can't fall behind.
- **Project URLs are flat and permanent** — `/projects/<name>/`. The category is metadata now, so re-filing a project doesn't move a page. Every old URL redirects.

</Changes>
</Release>

<Release version="1.14.0" date="August 1, 2026">

Catches the docs up with brAIn 1.16.0 — a conversations rail, a model and context readout, and a third way off the findings list.

<Changes type="added">

- **[Dismiss](/brain/findings/#dismiss-which-is-neither)** on the Findings page. It clears a card and teaches brAIn nothing, so the next analysis is free to find the same thing again — as opposed to **Ignore**, which is a judgement that the thing is normal here. A table now says plainly what each of the three exits teaches brAIn, because that is the only difference between them that matters.
- **[The conversations rail](/brain/terminal/#on-a-wide-screen-a-rail-of-conversations)** — from about 1100px the chat grows a column listing every conversation, with the one you're in marked. Same list and same resume as the ⋯ menu; below that width it isn't drawn and the menu is still the way in.
- **[Which model, and how full](/brain/terminal/#which-model-and-how-full)** — the model answering and the context in use, under the message box. The number is what the CLI reports it sent on the last turn, so it's measured rather than estimated; cached parts count, because a cached prompt still occupies the window.

</Changes>
<Changes type="changed">

- **"A new chat doesn't lose the old one."** The docs, and the panel's own prompt, used to say the conversation was cleared and Claude forgot its context. Claude Code keeps it and it stays in the list — what a new chat actually costs is that the next thing you say belongs to a separate conversation.

</Changes>
</Release>

<Release version="1.13.0" date="July 31, 2026">

Catches the docs up with brAIn 1.15.0, and reshoots the screenshots against a demo home whose numbers survive being checked.

<Changes type="changed">

- **The findings buttons are shorter, and the docs say so.** *"Not a problem here"* is now **Ignore**, *"I've fixed it"* is **I fixed it**. What each ending teaches brAIn hasn't changed — it's in the tooltip now rather than in the label.
- **Answered is gone, on the [Findings](/brain/findings/) page and in the panel.** Settling a finding writes the answer into [memory](/brain/memory/) and deletes the row, so an Answered list was a pile of dismissed cards beside a work list that's meant to empty. Memory is the record. The page now explains where answers actually go, and warns plainly that Ignore is permanent.
- **New screenshots**, reshot against a corrected demo home.

</Changes>
<Changes type="fixed">

- **The numbers in the screenshots now survive arithmetic.** The energy card claimed the dehumidifier drew more than the fridge, freezer and both TVs combined while the chart underneath showed 41 kWh against 46; it billed 41 kWh at 28.6p as £14.20 when that is £11.73; and it put a 1930s British semi's dehumidifier in a basement. Every figure in the demo home is now checkable, which matters more here than anywhere — the whole pitch is that brAIn's numbers are real. The house is generated by a harness committed alongside the add-on, so the next reshoot starts from the same corrected facts.

</Changes>
</Release>

<Release version="1.12.0" date="July 31, 2026">

New lead copy on the [brAIn overview](/brain/), matching the READMEs and the add-on's own documentation, plus a correction to what the docs claimed brAIn can't do to YAML.

<Changes type="changed">

- **The overview leads with the pitch, not the parts list.** *Your house already has nerves. Now give it a brAIn.* The "What it is" section that follows says what the thing does in four short paragraphs — sees the whole system and can change any of it, keeps a memory you can open and edit, reachable as a conversation agent or a chat interface or native Claude Code, callable from your automations.
- **This changelog moved out of the sidebar and into the header.** A page about what changed on the docs site had the same weight in the nav as the projects people actually come here for. It is now the small version number beside the social icons — click it and you land here. The version is read from `package.json` at build time, so it can't disagree with the release it shipped in. It hides below 50rem, where the header is already tight.
- **Changelog cards are a lighter grey in light mode.** They used Starlight's `--sl-color-gray-6`, a blue-tinted `#edeef3` that on a white page read as a shaded panel rather than a card. Now a plain neutral `#fafafa` with the border defining the edge. Dark mode is unchanged — there, a lifted surface is what makes a card read as one.

</Changes>
<Changes type="fixed">

- **brAIn can edit YAML-defined dashboards, helpers and persons** — the docs implied otherwise in four places. The registry *services* decline them, because a `brain.*` service edits the registry and a YAML-defined object isn't in it; brAIn then opens the file, edits it, validates it and reloads the domain. Same outcome, different layer, and `brain undo` covers both. It was listed under "deliberately excluded", which read as a gap in what brAIn can reach rather than the routing detail it is. Now explained at [YAML config is not an exception](/brain/how-brain-controls-ha/#yaml-config-is-not-an-exception).
- **The dashboards page no longer promises a git config backup** that was removed from the add-on some releases ago. Dashboard edits are covered by the automatic per-dashboard config backup and by `brain undo`.

</Changes>
</Release>
