BRUH Insights is Claude in an analyst's chair. Here's the machinery behind each card, and the dials you have over it.

## The pipeline

For each insight category (and every Ask question), the add-on:

1. **Collects a slimmed snapshot** of your home through the Supervisor API — entity states with areas and friendly names, recent history for relevant sensors, and long-term statistics for energy. GPS coordinates never leave the house; only zone/state and areas are included.
2. **Sends it to Claude** (headless Claude Code CLI) with a strict design system — colorblind-safe palette, proper chart rules, dark & light mode, hover interactivity.
3. **Stores and renders the result** — title, summary, highlight stats, and a self-contained HTML visualization, rendered in a sandboxed iframe (`sandbox="allow-scripts"`; it cannot touch your HA session).

Insights persist across restarts, refresh on their own schedules, and generation runs one-at-a-time through a queue to stay friendly to subscription rate limits.

## The analyst remembers

What separates Insights from "chart of the week": a local knowledge base with a lifecycle.

- **Questions** — the analyst may attach up to two *clarifying questions* to a card, only when a genuine blocker would change future analyses. Answer inline (or hit ✕ *not relevant* to retire a line of inquiry); every question is tracked **open → answered/dismissed** with a hard never-re-ask rule.
- **Findings** — durable discoveries (a flaky sensor, a recurring pattern) are deduplicated and fed back into every future run as facts to build on, not rediscover.
- **Previous runs** — each category sees its own last run and is instructed to lead with *what changed*.
- **The home memory file** — the 🧠 Memory dialog shows and edits `/config/.bruh_claude/memory/memory.md`, whose contents are folded into every snapshot. Teach it something in the "Teach it something" box and Claude merges it into the document — deduplicated, newest-wins.
- **Feedback** — 💬 on any card records standing instructions (*"show costs in dollars"*) injected into every future generation until removed.

:::tip[Shared with BRUH Terminal]
Findings and answers are handed to the `bruh_claude` integration (`add_memory` / `answer_question`), and the memory file is the same one BRUH Terminal's `ha-memory` maintains — so what the analyst learns, your voice assistant knows, and vice versa. Without the Terminal installed, everything still works locally with `/share` drop-file fallbacks. Full story: [Terminal + Insights, better together](/bruh-claude/better-together/).
:::

## Deep presence

For Overview, Presence, and every Ask question, the add-on walks the device registry and includes sibling entities from each presence tracker's physical device — the companion-app phone's WiFi SSID, geocoded address, activity, battery and charging state, with recent history. The analyst must cite its evidence (*"phone on home WiFi and charging since 10:41 PM"*), not parrot `home`/`not_home`.

## Token budgets

The ⚙ Settings dialog governs spend without a restart:

- **Automatic insights** — the master switch; off pauses all scheduled runs while manual Generate/Ask still work.
- **Session usage budget** — *let Insights use up to N% of each 5-hour session window*. Once reached, automatic runs pause until the window rolls over; manual clicks are never blocked.
- A **topbar chip** keeps session usage and reset time in view (*"34% used · resets 3:15 PM"*).

With **BRUH Terminal installed**, the meter uses your **real Anthropic account utilization** from its usage-limits tracker — all Claude use on the account counts, so Insights automatically backs off when *you're* using Claude elsewhere. Standalone, it estimates from its own runs.

## Schedules, custom insights, history

- **Per-category schedules** — an interval or fixed daily times (`07:00, 19:00`) per card; fixed times take precedence and spend nothing in between.
- **Custom insights** — ＋ New insight creates fully custom recurring cards (up to 24); promote any Ask answer with *＋ Make recurring*.
- **History** — every run is stored (per `history_keep_runs`/`history_keep_days`); each card has a run selector with prev-run comparisons on highlight stats.
- **Tags** — the analyst tags cards by what it found (`#anomaly`, `#batteries`, `#left-on`); the chip row filters live.

## Dashboard cards, portless

Press **▦** on any card for ready-to-paste YAML:

```yaml
type: iframe
url: /local/bruh_insights/energy-<your-card-token>.html
title: Energy
aspect_ratio: 90%
```

The add-on mirrors insight HTML into `/config/www/bruh_insights/`, so the card is served by **Home Assistant itself** — same-origin, works on LAN, local SSL, and Nabu Casa remote access with no port mapping. The file name embeds a per-install random token; the mirror holds only insight HTML — no API, no credentials.
