## What it is

A Home Assistant add-on that runs **Claude Code** inside HA and gives it a memory of your house. One ingress panel carries three faces — an **insights dashboard**, a **full terminal**, and the **memory** itself — plus a voice assistant, scheduled reports, and 56 admin services. It reads your entities, services, automations, traces, history, cameras, and logs through a built-in MCP server, so it actually knows your setup rather than guessing at it.

BRain replaces **BRUH Terminal** and **BRUH Insights**, which were two add-ons, two logins, and two memories racing on one file.

## The learning loop

This is the part that makes it more than a chat window:

1. **It studies.** A study session digs into one topic — naming, occupancy, energy, climate, device reliability — and files what it found.
2. **It guesses.** When it believes something but can't confirm it, it says so in a form you can answer with one tap: *"The garage fridge is meant to run 24/7 — right?"* Three open at a time, never more.
3. **You settle it.** ✓ files it as a plain memory line. ✗ records a dead end that is never revisited.
4. **Everything reads it.** Voice prompts, insight runs, and the terminal's generated context all draw on the same document — so answering a guess in the panel makes your voice assistant smarter.

`sensor.brain_facts_learned` and a `brain_learned` logbook event put that loop in your home's timeline, next to the lights and doors. Details: **[Memory & Learning](/brain/memory/)**.

## Built for Home Assistant

What makes this different from running Claude Code on a regular machine:

- **Your Claude subscription covers it** — OAuth sign-in, so Pro/Max includes your usage; an API key works too. **One login** covers the panel, the terminal, voice, insights, and memory.
- **[36 purpose-built MCP tools](/brain/mcp/)** — live states, device control, cameras, history and statistics, registries, dashboards, traces, templates, logs, reloads. How the layers fit: [How BRain controls your home](/brain/how-brain-controls-ha/).
- **Auto-generated context** — every boot regenerates `/config/CLAUDE.md`, a snapshot of your install that Claude reads at the start of each session.
- **Usage-limit sensors** — the same session/weekly utilization as claude.ai → Settings → Usage, as HA sensors with reset times.
- **Safe by default** — voice agents get HA tools but no shell, file, or web access; per-agent blocked-services lists; non-root sandbox.
- **Two CLI commands, not fourteen** — `brain` for its own faculties, `ha` for Home Assistant chores. [The CLI](/brain/cli/).

## What it doesn't do

Honesty up front. BRain **can't add or remove integrations** (config flows are interactive — OAuth, pairing buttons — so it walks you to the right screen and you click), **never touches credentials** (API keys, tokens, MFA), and **won't edit YAML-mode dashboards through services** (it edits the YAML itself instead).

It also **doesn't back up your configuration** — Home Assistant's own backups already do that, whole-system and restorable. What BRain keeps is an edit journal of the files *it* touched, so `brain undo` can put one back.

The full scorecard: [what BRain can and can't reach](/brain/how-brain-controls-ha/#what-brain-can-and-cant-reach).
