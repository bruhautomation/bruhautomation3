The terminal ships a toolbox of `ha-*` commands so common Home Assistant chores are one line — for you *and* for Claude, which uses them constantly. <Detail inline min={2}>These cover the **file-and-workflow side** (YAML, logs, backups, memory) that live APIs don't; the live home belongs to the [MCP tools](/bruh-claude/mcp/), and admin changes to [Power Tools](/bruh-claude/power-tools/) — see [how the layers fit](/bruh-claude/how-claude-controls-ha/).</Detail>

<Detail max={1}>

Three worth knowing from day one:

- **`ha-selftest`** — run this when anything misbehaves. It checks the whole stack end-to-end and prints PASS/FAIL with a fix hint for each part.
- **`ha-backup`** — snapshot your config to git before an experiment (automatic backups run on an interval too).
- **`ha-log`** — watch Home Assistant's logs live.

You rarely need to remember the rest: just ask Claude — *"back up my config"*, *"check the logs for zigbee errors"* — and it picks the right tool. The full command reference is one notch up on the **Detail** slider.

</Detail>

## Daily drivers

| Command | What it does |
|---------|--------------|
| `ha-reload <target>` | Reload HA config: `automations`, `scripts`, `scenes`, `groups`, `core`, `all` |
| `ha-log [core\|supervisor\|addons]` | Tail HA logs in real time |
| `ha-entity <action> <id>` | Get/set entity states: `get`, `set`, `list`, `search` |
| `ha-service call <domain>.<service>` | Call any HA service from the shell |
| `ha-yaml-check` | Validate YAML before reloading |
| `ha-notify "msg"` | Send a persistent or mobile push notification |
| `ha-addon <action> <slug>` | Manage add-ons: `list`, `info`, `restart`, `stop`, `start`, `logs`, `options` |

## Backup & context

| Command | What it does |
|---------|--------------|
| `ha-backup [message]` | On-demand git commit of `/config` (auto-backup also commits on an interval — every edit session is recoverable) |
| `ha-context-gen` | Regenerate `/config/CLAUDE.md`, the [context file](/bruh-claude/mcp/#generated-context) Claude reads each session |

## Memory, sharing, diagnostics

| Command | What it does |
|---------|--------------|
| `ha-memory <action>` | The [long-term memory](/bruh-claude/memory/): `add`, `list`, `inbox`, `questions`, `answer`, `consolidate`, `edit`, `clear` |
| `ha-share-login` | Share your Claude login with other BRUH add-ons — this is the one-liner that [connects BRUH Insights](/bruh-claude/better-together/#one-login) (`--status`, `--revoke`) |
| `ha-share <action>` | Cross-add-on file sync via `/share`: `push`, `pull`, `ls` |
| `ha-selftest` | **Run this first when anything misbehaves** — drives the whole stack end-to-end (MCP, auth, listeners, worker pool) and prints PASS/FAIL with a fix hint per part |
| `persist-install apk\|pip <pkgs>` | Install packages that survive add-on restarts |

</Detail>

## Everything is Claude-usable

Claude's generated context lists every tool, so *"reload automations"*, *"check the logs for zigbee errors"*, or *"back up my config before we start"* resolve to the right command.
