The feedback loop. `find_orphaned_references` scans every automation, script, and scene for references to entities Home Assistant doesn't know — the silent breakage left behind by renames, removed integrations, and typos. It never changes anything; it reports (and can optionally raise a repair issue with the findings).

`create_repair_issue` gives Claude — and your automations — a first-class way to flag things in **Settings → System → Repairs**: persistent, severity-tagged, dismissible. An insight job that spots a failing sensor, a night-audit automation that finds an open gate — they can now leave a proper paper trail instead of a notification that scrolls away.

## Find orphaned references

**`bruh_claude.find_orphaned_references`** — Scan every automation, script, and scene for references to entities Home Assistant doesn't know (renamed, deleted, or typo'd). Returns the findings as response data; optionally raises a repair issue listing them.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `create_issue` | boolean | no | Also surface the findings in Settings > System > Repairs. |

```yaml
service: bruh_claude.find_orphaned_references
response_variable: findings

# Or surface the results as a repair issue
service: bruh_claude.find_orphaned_references
data:
  create_issue: true
```

> 🗣️ *"Do any of my automations still reference entities that don't exist?"* — works in the terminal, by voice, or in an automation prompt.

## Create repair issue

**`bruh_claude.create_repair_issue`** — Create a custom issue in Settings > System > Repairs — a persistent, dismissible way to surface something that needs the user's attention. Returns the issue_id as response data.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `title` | text | **yes** | Short title of the issue. |
| `description` | text | **yes** | Full description shown when the issue is opened. |
| `severity` | select | no | How serious the issue is (default warning). |
| `persistent` | boolean | no | Keep the issue across Home Assistant restarts. |
| `issue_id` | text | no | Optional stable ID so the issue can be removed or replaced later. Auto-generated when omitted. |

```yaml
service: bruh_claude.create_repair_issue
data:
  title: "Low battery: front door lock"
  description: "The front door lock reported 8% battery. Replace soon."
  severity: warning
  issue_id: front_lock_battery
```

> 🗣️ (Claude uses this itself — e.g. an insight job that finds a failing sensor can flag it in Repairs.)

## Remove repair issue

**`bruh_claude.remove_repair_issue`** — Remove a previously created repair issue by its issue ID.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `issue_id` | text | **yes** | The issue_id used (or returned) when the issue was created. |

```yaml
service: bruh_claude.remove_repair_issue
data:
  issue_id: front_lock_battery
```

> 🗣️ *"The lock battery is replaced — clear that repair issue."* — works in the terminal, by voice, or in an automation prompt.
