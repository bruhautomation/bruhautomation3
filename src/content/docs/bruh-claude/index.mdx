## What it is

<Detail max={1}>

A Home Assistant add-on that puts **Claude** — the AI assistant — inside your smart home. Talk to it out loud, type to it in a terminal, schedule it to watch the house, or let your automations call it. It knows *your* rooms, *your* devices, and *your* history, so you can just ask: *"why is the hallway light on?"*

</Detail>

<Detail min={2}>

A Home Assistant add-on that runs **Claude Code** inside HA, with native access to your entities, services, automations, traces, history, cameras, and logs through a built-in MCP server. Open a terminal in your sidebar, talk to it through Voice Assistants, schedule it to watch your house, or call it from automations. Either way, Claude actually knows your setup.

</Detail>

## What you can do

<CardGrid>
  <Card title="Fast voice assistant" icon="comment-alt">
    Pick **BRUH Claude** in **Settings → Voice Assistants**. Typical commands answer in ~3–5 s, replies stream for TTS, and follow-ups remember the conversation.
  </Card>
  <Card title="Scheduled insight reports" icon="rocket">
    Claude watches your house and writes markdown reports to sensors: daily briefing, anomaly watch, battery check, or your own templated prompt — with ready-to-paste dashboard YAML.
  </Card>
  <Card title="Reorganize by asking" icon="puzzle">
    **[Power Tools](/bruh-claude/power-tools/)**: 56 admin services for areas, labels, entities, helpers, dashboards, zones, and users. *"Rename all the Shellys"*, *"build me a guest-mode toggle"* — validated, admin-gated, no `.storage` edits.
  </Card>
  <Card title="Debug your automations" icon="error">
    Claude reads automation traces and cross-references state and history to tell you exactly why something fired — or didn't.
  </Card>
  <Card title="See your cameras" icon="seti:image">
    Claude looks at a camera and tells you what it sees: *"is the garage door actually closed?"* — by voice or in an automation.
  </Card>
  <Card title="Trigger from automations" icon="setting">
    `bruh_claude.run_task` runs Claude in the background — error-log digests, config audits, morning summaries — with an optional done-notification.
  </Card>
  <Card title="Ask anything" icon="information">
    Live state and real history: *"How cold did it get last night?"*, *"Which automations haven't run in 30 days?"*
  </Card>
</CardGrid>

## Built for Home Assistant

What makes this different from running Claude Code on a regular machine:

<Detail max={1}>

- **Your Claude subscription covers it** — sign in with your Claude account (Pro/Max), or use an API key.
- **It genuinely knows your home** — live states, history, cameras, and every device, refreshed automatically. No copy-pasting entity lists.
- **Safe by default** — voice can control the house but can't run shell commands or read files, and you can block specific services per agent.
- **Your config is always recoverable** — automatic git backups of `/config`, with single-file restore.

</Detail>

<Detail min={2}>

- **Your Claude subscription covers it** — OAuth sign-in, so Pro/Max includes your usage; an API key works too.
- **[36 purpose-built MCP tools](/bruh-claude/mcp/)** — live states, device control, cameras, history and statistics, registries, dashboards, traces, templates, logs, reloads. How the layers fit: [How Claude controls your home](/bruh-claude/how-claude-controls-ha/).
- **Auto-generated context** — every boot regenerates `/config/CLAUDE.md`, a snapshot of your install that Claude reads at the start of each session.
- **Usage-limit sensors** — the same session/weekly utilization as claude.ai → Settings → Usage, as HA sensors with reset times.
- **Safety layers** — voice agents default to HA tools only (no shell, file, or web access); per-agent blocked-services lists are enforced at the MCP `call_service` chokepoint; everything runs in a non-root sandbox.
- **Git-based config backup** — auto-commits of `/config` on an interval, manual `ha-backup`, single-file restore from any commit.

</Detail>

## What it doesn't do

Honesty up front: Claude **can't add or remove integrations** (config flows are interactive — OAuth, pairing buttons — so it walks you to the right screen and you click), **never touches credentials** (API keys, tokens, MFA), and **won't edit YAML-mode dashboards through services** (it edits the YAML itself instead). The full scorecard: [what Claude can and can't reach](/bruh-claude/how-claude-controls-ha/#what-claude-can-and-cant-reach).

**[Quick Start →](/bruh-claude/quickstart/)** — add the repo, install, restart HA once, sign in. About five minutes.
