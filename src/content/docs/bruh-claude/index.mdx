## What it is

A Home Assistant add-on that runs **Claude Code** inside HA — with native access to your entities, services, automations, traces, history, cameras, and logs through a built-in MCP server. Open a terminal in your sidebar, talk to it through Voice Assistants, schedule it to watch your house, or call it from automations. Either way, Claude actually knows your setup.

![BRUH Claude Terminal architecture overview](/images/bruh-claude/architecture-overview.svg)

## What you can do

<CardGrid>
  <Card title="Fast voice assistant" icon="comment-alt">
    Pick **BRUH Claude** as a conversation agent in **Settings → Voice Assistants**. Pre-warmed workers answer typical commands in ~3–5s, replies stream so TTS starts at the first sentence, and follow-ups remember the conversation. *"Turn off the kitchen lights"* acts directly — no entity lookups.
  </Card>
  <Card title="Proactive insight reports" icon="rocket">
    Schedule Claude to watch your house and write **markdown reports to sensors** — daily briefing, anomaly watch, battery & maintenance, camera check, or your own templated prompt. Each report comes with ready-to-paste dashboard card YAML.
  </Card>
  <Card title="See your cameras" icon="seti:image">
    Claude can *look* at a camera and tell you what it sees — *"is the garage door actually closed?"*, *"is anyone in the driveway?"* — by voice or in an automation.
  </Card>
  <Card title="Debug your automations" icon="error">
    Claude reads automation traces, cross-references entity state and history, and tells you *exactly* why something fired — or didn't. No more grepping `home-assistant.log`.
  </Card>
  <Card title="Trigger from automations" icon="setting">
    The `bruh_claude.run_task` service runs Claude in the background — error-log digests, config audits, morning summaries — with an optional notification when it's done.
  </Card>
  <Card title="Just… ask anything" icon="information">
    *"How cold did it get last night?"* *"Which automations haven't run in 30 days?"* *"What's the weather tomorrow?"* Live state, real history, real answers.
  </Card>
</CardGrid>

## Built for Home Assistant

What makes this different from running Claude Code on a regular machine:

<CardGrid>
  <Card title="Use your Claude subscription" icon="approve-check">
    Authenticates with Anthropic via **OAuth**, so a Claude **Pro** or **Max** subscription covers your usage. No API key, no pay-per-token billing for everyday use (an API key works too if you prefer).
  </Card>
  <Card title="Live HA awareness (MCP server)" icon="puzzle">
    A built-in MCP server gives Claude **32 purpose-built tools** — entity states, device control for every domain, camera snapshots, history & statistics, weather forecasts, areas, automation traces, templates, logs, config reload. No manual API setup.
  </Card>
  <Card title="Auto-generated context" icon="information">
    On every boot the add-on regenerates `/config/CLAUDE.md` — a snapshot of your entities by domain, automations with last-triggered times, installed integrations, and your file tree. Claude reads it at the start of every session.
  </Card>
  <Card title="Usage-limit sensors" icon="seti:graphql">
    The same session and weekly utilization you see on **claude.ai → Settings → Usage**, surfaced as HA sensors with reset timestamps. Build a dashboard, set an alert before you hit a limit.
  </Card>
  <Card title="Safe by default" icon="seti:lock">
    Voice agents get every HA tool but **no** shell, file, or web access — and a per-agent **Blocked services** list can bar a kitchen speaker from unlocking doors. Everything runs sandboxed as a non-root user.
  </Card>
  <Card title="Git-based config backup" icon="document">
    Auto-commit `/config` every 30 minutes (configurable). `ha-backup` for manual snapshots, single-file restore from any commit, sensible `.gitignore` that excludes secrets.
  </Card>
</CardGrid>

## Usage & insight sensors

Two kinds of sensors land in Home Assistant once the integration is set up.

**Usage-limit sensors** — your real Anthropic account utilization, not estimates:

| Sensor | Tracks |
|--------|--------|
| `sensor.bruh_claude_session_usage` | Percent of the current 5-hour session window used |
| `sensor.bruh_claude_weekly_usage` | Percent of the rolling 7-day window used |
| `…_session_usage_resets_at` / `…_weekly_usage_resets_at` | When each window resets |

These mirror **claude.ai → Settings → Usage** and need an **OAuth / subscription login** (not an API key).

**Insight sensors** — one `sensor.<job>_insight` per scheduled job, holding the latest report in its `markdown` attribute plus ready-to-paste `card_yaml`. A `binary_sensor` also reports voice-assistant health (worker count and latency).

![A BRUH Claude insight report rendered as a Markdown card on a Home Assistant dashboard](/images/bruh-claude/insight-report-card.svg)

## Up and running in 5 minutes

1. Add the **BRUH HA Apps** repository in HA.
2. Install **BRUH Claude Terminal** and start it.
3. Restart Home Assistant once (so HA loads the integration).
4. Accept the discovered **BRUH Claude** integration.
5. Authenticate with Anthropic in the terminal — then start typing, or pick it as your voice assistant.
