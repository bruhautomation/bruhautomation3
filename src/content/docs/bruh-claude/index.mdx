## What is BRUH Claude?

BRUH Claude Terminal is a Home Assistant add-on that gives you a full Claude Code environment inside your HA instance — with native access to the Home Assistant API, automatic config backups, and deep integrations that let Claude act as a conversation agent or run tasks triggered by your automations.

It's not just a terminal. It's an AI assistant that *understands* your smart home.

## How It Works

BRUH Claude runs as a Home Assistant add-on container with three main layers:

<div style="margin: 2rem 0;">
  <img src="/images/bruh-claude/architecture-overview.svg" alt="BRUH Claude Architecture Overview" style="width: 100%; border-radius: 8px;" />
</div>

The **Web Terminal** (ttyd + tmux) gives you an interactive Claude Code session. The **MCP Server** connects Claude to the HA Supervisor API with 14 purpose-built tools. And the **IPC Listeners** bridge Claude to HA's conversation agents and automation system using a file-based messaging protocol.

## Quick Example

Here's what working with BRUH Claude looks like. Just open the terminal and ask:

```
> Help me debug why my living room motion automation isn't triggering

I'll investigate this for you. Let me check the automation and related entities.

✓ Found automation "Living Room Motion Lights" (automation.living_room_motion_lights)
✓ Automation is enabled, last triggered 3 days ago
✓ Checking entity: binary_sensor.living_room_motion — state: "unavailable"

The issue is clear: your motion sensor (binary_sensor.living_room_motion) is showing
"unavailable", which means the automation's trigger will never fire.

This usually means:
1. The sensor has lost connectivity (battery dead, out of range)
2. The integration providing it needs to be reloaded

Would you like me to check the device registry for more details on this sensor?
```

Claude doesn't just read your config files — it queries live entity states, checks automation traces, and cross-references the device registry to give you real answers.
